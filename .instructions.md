# NOVA Electronics Store – Local Dev Startup

## Stack

- **Monorepo**: npm workspaces + Turborepo
- **Backend**: Medusa v2 (2.17.0), MikroORM, PostgreSQL
- **Storefront**: Next.js 15, React 19, Three.js, GSAP, Framer Motion, TailwindCSS 4
- **Node.js**: v20+ required (tested with v20.19.6)

## Prerequisites

- Node.js >= 20
- Docker (for PostgreSQL)

## Startup Steps (in order)

### 1. Start PostgreSQL

```sh
docker compose up -d
```

Container: `nova_postgres`, port 5432, db: `nova_store`, user/pass: `postgres/postgres`

### 2. Install Dependencies

```sh
npm install
```

**Known issues:**
- The root `package.json` has `overrides` pinning all `@mikro-orm/*` to `6.6.14` — this is required because `@medusajs/deps` pins 6.6.14 and version mismatches cause runtime errors.
- If `npm install` reports invalid peer deps for mikro-orm, delete `package-lock.json` and retry.
- `@medusajs/medusa` needs several deps that may not hoist properly in the workspace. If you get `MODULE_NOT_FOUND` errors for packages like `request-ip`, `@inquirer/checkbox`, `multer`, `node-schedule`, `slugify` — install them in the backend workspace: `npm install <pkg> -w apps/backend`

### 3. Symlink @medusajs/medusa to root (hoisting fix)

The `@medusajs/utils` package (hoisted to root) tries to resolve `@medusajs/medusa/link-modules` but `@medusajs/medusa` lives in `apps/backend/node_modules`. Create a junction:

```powershell
node -e "const fs=require('fs'); const src='apps/backend/node_modules/@medusajs/medusa'; const dest='node_modules/@medusajs/medusa'; if(!fs.existsSync(dest)){fs.symlinkSync(require('path').resolve(src), dest, 'junction'); console.log('Symlinked')} else {console.log('Already exists')}"
```

### 4. Run Database Migrations

```sh
cd apps/backend
npx medusa db:migrate --execute-safe-links
```

### 5. Seed Database

```sh
cd apps/backend
npx medusa exec ./seed.ts
```

Seeds: 8 products, 7 categories, 4 collections, shipping options, region (US), sales channel.

### 6. Start Backend

```sh
cd apps/backend
npx medusa develop
```

Runs on **http://localhost:9000**. Admin UI at **http://localhost:9000/app**.

### 7. Start Storefront

```sh
cd apps/storefront
npx next dev -p 3000
```

Runs on **http://localhost:3000**.

## Reset Database

```sh
docker exec nova_postgres psql -U postgres -c "DROP DATABASE IF EXISTS nova_store;"
docker exec nova_postgres psql -U postgres -c "CREATE DATABASE nova_store;"
cd apps/backend
npx medusa db:migrate --execute-safe-links
npx medusa exec ./seed.ts
```

## Gotchas

1. **Always `cd` into `apps/backend` before running `npx medusa` commands** — the CLI checks for `medusa-config.ts` in cwd.
2. **MikroORM version alignment is critical** — all `@mikro-orm/*` packages must be the same version (6.6.14 for Medusa 2.17).
3. **The seed script was patched** for Medusa 2.17 API changes: `IStockLocationModuleService` → `IStockLocationService`, `createFulfillmentSetsWorkflow` replaced with direct service call, `variant.sku` null guard added.
4. **Redis is optional** — the config uses in-memory event bus, cache, and workflow engine.
5. **Admin panel needs `@medusajs/ui` resolvable from the repo root.** The admin bundler builds Tailwind's `content` glob list as `[html, root, @medusajs/dashboard, @medusajs/ui, ...]`. If `@medusajs/ui` can't be resolved it becomes an empty string, and Vite/PostCSS fails with `[postcss] Patterns must be a string (non empty)` (fast-glob) — the admin shows a CSS error overlay. Fix: ensure `@medusajs/ui@4.1.17` (the version pinned by `@medusajs/dashboard@2.17.0`) is installed at the root. Because the root carries a stray `react-dom@^19.2.7` while `@medusajs/ui` peers on React 18, install it with `--legacy-peer-deps`: `npm install @medusajs/ui@4.1.17 --legacy-peer-deps`. Restart `medusa develop` afterward (the Tailwind config is built at startup). Note: any plain `npm install` may also need `--legacy-peer-deps` for the same react-dom reason.
