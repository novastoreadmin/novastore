# Analytics — розширення адмінки

Пункт меню **Analytics** (іконка графіка) — чотири дашборди з фільтром за
датами (пресети 7/30/90 днів + довільний діапазон).

## Вкладки

| Вкладка | Що показує | Джерело |
|---|---|---|
| **E-commerce** | дохід, замовлення, середній чек, Monobank списано/заблоковано, дохід і замовлення за днями, топ товарів, оплати за провайдерами, **План vs Факт** | замовлення + платежі з нашої БД |
| **Логістика** | ВЕСЬ потік: створені-але-не-відправлені замовлення («Очікує відправлення») + відправлення НП; **мапа України** з точками міст доставки (помаранчева = є очікуючі, зелена = все доставлено, розмір = кількість, тултип із вартістю); % доставлених, вартість доставки (НП-тариф або оплачена клієнтом для очікуючих), донат статусів, топ міст з очікуючими та вартістю | замовлення з НП-методом + fulfillment-и з `np_ttn`; статуси — з metadata, які пише Sync у розширенні Nova Poshta; координати міст — `src/lib/ua-cities.ts` (~55 міст; місто без координат лишається в таблицях без точки) |
| **Поведінка** | кошики, конверсія в покупку, воронка (кошики → контакти → замовлення), нові vs повторні, замовлення за годинами | кошики + замовлення |
| **Клієнти** | всього/нових/активних клієнтів, % повторних, нові за днями, гість vs зареєстрований | клієнти + замовлення |

## Архітектура

```
Admin UI (src/admin/routes/analytics/page.tsx)
  розкладки за зразком дашбордів TailAdmin (ряд KPI → тренди → розбивки →
  таблиці), зібрані з Medusa UI; графіки — власні легкі SVG без залежностей
        ▼
GET /admin/analytics?from&to (src/api/admin/analytics/route.ts)
  один агрегований JSON; захищено штатною admin-автентифікацією
        ▼
src/lib/analytics.ts — чисті функції агрегацій (юніт-тести)
src/lib/analytics-targets.ts — планові цілі з фінмоделей власника
```

- **Ніяких зовнішніх викликів**: цифри Monobank — зі збережених платежів,
  цифри НП — зі збережених fulfillment-ів. API-ключі назовні не виходять.
- ВАЖЛИВО (граблі query.graph): для замовлень треба вибирати `items.*` —
  частковий вибір підполів item-ів ламає обчислений `total` і губить
  `quantity` (закоментовано в роуті).

## Вкладка Логістика (розкладка за TailAdmin logistics)

- **KPI з трендами** проти попереднього рівного періоду (зелений/червоний бейдж).
- **«Статистика доставки»** — парні стовпчики відправлено vs доставлено за днями
  (день доставлених — наближення за днем створення ТТН, дата фактичної
  доставки НП не зберігається).
- **«Відстеження доставки»** — таймлайн Створено → В дорозі → Доставлено для
  обраного відправлення; вибір через випадаючий список (Medusa UI `Select`, а
  не сирий `<select>`) над таймлайном (раніше показувалось лише останнє
  відправлення), або клік по рядку в «Активності доставок», з ТТН-лінком на
  трекінг НП.
- **Мапа з перемикачами станів**: чекбокси Очікує / Створено-в-дорозі /
  Доставлено фільтрують точки; розмір точки = кількість видимих посилок.
- **Кольори статусів НП уніфіковані** з розширенням Nova Poshta через спільний
  модуль `src/admin/lib/np-status-badge.tsx` (`NpStatusBadge`, `npStatusKey`,
  `NP_STATUS_HEX`) — бейджі виглядають однаково в обох місцях: невідомо=сірий,
  очікує=помаранчевий, створено=темно-помаранчевий, в дорозі=жовтий,
  прибув=синій (з пульсацією в режимі очікування "arrived"), отримано=зелений,
  видалено=червоний, відмова/повернення=темно-червоний (відрізняється від
  видалено). Сирий код статусу "1"/"100" замінюється коротким лейблом
  «Створена накладна» через `STATUS_LABEL_OVERRIDES` у `src/lib/analytics.ts`.
- **«Статистика доставки»** тепер фарбує стовпчики «Доставлено» зеленим
  (`C.green = #10b981`), «Відправлено» лишається блакитним.
- **«Активність доставок»** — таблиця всіх позицій потоку з чипами статусів
  (Всі/Очікує/Створено/В дорозі/Доставлено) і пагінацією по 5.

### Google Maps на мапі доставок

Мапа реалізована за офіційним туторіалом Google Maps Platform + deck.gl
(GoogleMapsOverlay + ScatterplotLayer, маркери кольору туторіалу
`[255, 133, 27]`). Ключ віддається бекендом у рантаймі
(`GET /admin/analytics/maps-config`, під admin-автентифікацією) — у бандл і
репозиторій не потрапляє. **Без ключа нічого не ламається**: рендериться
вбудована SVG-мапа України.

Увімкнення на продакшні:

1. [Google Cloud Console](https://console.cloud.google.com/) → створити
   проєкт (або взяти наявний) → увімкнути **Maps JavaScript API** →
   Credentials → **Create API key**.
2. ОБОВ'ЯЗКОВО обмежити ключ: *Application restrictions → Websites* →
   `https://api.novastore.com.ua/*`; *API restrictions* → лише Maps
   JavaScript API. (Ключ браузерний — обмеження за referrer і є його захист.)
3. На дроплеті додати в `~/novastore/apps/backend/.env`:

   ```bash
   GOOGLE_MAPS_API_KEY=AIza...ваш_ключ
   # опційно, для векторного стилю (Map Style у консолі GMP):
   # GOOGLE_MAPS_MAP_ID=xxxxxxxxxxxxxxxx
   ```

4. Продублювати у файл, який читає прод-процес, і перезапустити:

   ```bash
   cp ~/novastore/apps/backend/.env ~/novastore/apps/backend/.medusa/server/.env.production
   pm2 restart medusa
   ```

   Rebuild НЕ потрібен — ключ читається в рантаймі. Вимкнути мапу Google
   можна, просто прибравши змінну (повернеться SVG-fallback).

### Тестові відправлення локально

Локально NP-ключа немає, тож для перевірки є `np-test-shipments.ts`
(dev-only): створює на 4 останніх замовленнях повну палітру станів —
очікує (Одеса) / створено (Київ) / в дорозі (Львів) / доставлено (Харків)
у точно тому форматі, який на проді пише реальний провайдер + Sync.

```bash
npx medusa exec ./np-test-shipments.ts           # створити
npx medusa exec ./np-test-shipments.ts cleanup   # прибрати
```

## План vs Факт — редагується в адмінці

Кнопка **«Налаштувати план»** на сторінці Analytics відкриває редактор усіх
планових параметрів (старт плану, ціль од./міс, середня ціна, змінні витрати,
маржа, розгін). Збереження йде в `store.metadata.analytics_targets`
(`GET/POST /admin/analytics/targets`) — без міграцій, переживає деплої;
«Скинути до моделі» повертає значення з файла. Хибні значення відкидаються
по-польово (`resolveTargets`), тож дашборд не зламати поганим збереженням.
**Це замінює ведення плану в Excel.**

Дефолти лежать у `src/lib/analytics-targets.ts`, куди перенесені
параметри з ваших таблиць (джерела задокументовані у файлі):

- старт плану **2026-07-01**, ціль **40 од./міс**, середня ціна **2523 ₴**
  (8 SKU за рекомендованої націнки 3×);
- розгін продажів: **20% → 100% за 6 місяців** (лінійно) — ціль місяця
  масштабується автоматично;
- змінні витрати **34%**, валова маржа **66.7%** → цільова чиста маржа
  ≈ **32.7%** (показується під прогрес-барами).

Прогрес-бар зелений, коли темп ≥ частки місяця, що минула; інакше
помаранчевий. Змінився план — правите числа в `analytics-targets.ts`, більше
нічого.

## Тести

`tests/unit/analytics.spec.ts` — 18 тестів: діапазони дат/серії днів,
e-commerce (дохід/AOV/топ/провайдери/captured-vs-authorized), логістика
(фільтрація скасованих і не-НП, статуси, міста), воронка/повторні, SaaS,
розгін і План-vs-Факт. Запуск: `npx vitest run tests/unit` з `apps/backend`.

## Обмеження (чесно)

- Агрегація по останніх 1000 замовлень/кошиків/клієнтів — точна на поточному
  масштабі; поріг у `SCAN_LIMIT` роуту.
- «Сесії» веб-трафіку не збираються (немає лічильника на сторфронті) —
  найближчий проксі це кошики; за потреби підключайте Plausible/GA окремо.
- Назви товарів у топі — снапшоти рядків замовлення: старі замовлення
  показують англійські назви, нові — українські.
- Статуси НП у логістиці оновлюються кнопкою Sync на сторінці Nova Poshta
  (або живуть з моменту останнього sync).
