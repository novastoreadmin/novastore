# DROPSHIP-KOSMOTECH.md — дропшип-модель Kosmotech: імплементація і перевірка

Kosmotech — дистриб'ютор аксесуарів (кабелі, зарядні, павербанки, накопичувачі),
B2B-кабінет `https://newb2b.kosmotech.com.ua/` (акаунт `business@novastore.com.ua`,
контрагент «Київ.Nova store», договір «Основной договор»). Договір дропшипу
підписано; перше тестове замовлення проведено 21.08.2026 (ПК000037088,
ТТН 20451516737013, статус «Відвантажене»).

Прочитай перед початком: [PAYMENTS-MONOBANK.md](PAYMENTS-MONOBANK.md),
[NOVAPOSHTA.md](NOVAPOSHTA.md), [TESTING.md](TESTING.md), правила пошти й
каталогу в [CLAUDE.md](../CLAUDE.md).

## 0. Модель грошей і правила (зафіксовано)

Ключова відмінність від класичного «постачальник збирає післяплату»: **гроші
клієнта завжди збирає NOVA** (Monobank-еквайринг або післяплата НП на рахунок
NOVA), **ТТН створює NOVA** зі свого бізнес-кабінету НП (наявний авто-ТТН флоу
без змін), а Kosmotech відвантажує посилку за цим номером — у їхньому чекауті
це спосіб доставки «Відправка по ТТН», який приймає ЛИШЕ номер ТТН і сам
підтягує ПІБ/телефон/місто/відділення отримувача з НП. Закупівельну вартість
Kosmotech виставляє NOVA окремо через B2B-баланс кабінету.

Наслідки:

| Кошик | Доступні оплати | Кому йдуть гроші | Хто робить ТТН |
|---|---|---|---|
| Тільки власні товари | Картка (Monobank) АБО Післяплата НП | NOVA | NOVA (авто-ТТН) |
| Тільки товари Kosmotech (`metadata.kosmotech`) | Картка (Monobank) АБО Післяплата НП — так само | NOVA | NOVA (авто-ТТН, той самий флоу) |
| Змішаний кошик | Заборонено у v1 | — | — |

- Персональні дані клієнта в Kosmotech НЕ передаються — кабінет бере їх з ТТН.
- Змішаний кошик заборонений, бо власні й дропшип-товари фізично їдуть з
  різних складів різними посилками (двi ТТН). v2 — авто-розбиття на два
  замовлення.
- Ціноутворення: закупівля за B2B-прайсом Kosmotech, продаж за цінами NOVA.

## 1. Товари в БД

Маркер дропшип-товару — `product.metadata.kosmotech` (об'єкт з `article` та
службовими полями). SKU варіанта = артикул Kosmotech (наприклад `T79CL`) —
саме він іде в Excel-імпорт кошика кабінету. Файл товарів від постачальника →
скрипт імпорту (буде додано, коли власник передасть файл; принципи ті самі:
адитивно, draft, `manage_inventory: false`, окремий shipping profile
Kosmotech). Закупівельні ціни — ТІЛЬКИ в gitignored
`apps/backend/data/kosmotech/`, у трекований код їх не вносити.

## 2. Оплата

Жодних спеціальних провайдерів: дропшип-кошики використовують ті самі
`pp_monobank_monobank` / `pp_cod_cod` (+ `pp_system_system` у dev), що й
власні. `allowedProviders()` у `src/lib/kosmotech-dropship.ts` повертає один
набір для "own" і "dropship"; guard-и лишаються тільки проти "mixed".

## 3. Класифікація кошика + серверні guard-и

Чиста логіка — `apps/backend/src/lib/kosmotech-dropship.ts` (без
Medusa-імпортів, юніт-тести в `tests/unit/kosmotech-dropship.spec.ts`):

- `classifyCart(items)` → own | dropship | mixed | empty (по `metadata.kosmotech`);
- `allowedProviders(kind)` → mixed/empty = [];
- `buildKosmotechImportRows(order)` → рядки `{article, count}` для Excel;
- `buildDropshipOrderText(order, ttn)` → текст заявки для ops/листа.

Серверні guard-и в `src/api/middlewares.ts` (фронту не довіряємо):

- `POST /store/carts/:id/line-items` — заборона змішування ще на етапі
  додавання (400 `dropship_cart_error`);
- `POST /store/carts/:id/shipping-methods` — дропшип-кошик може обрати лише
  дропшип-опцію і навпаки;
- `POST /store/payment-collections/:id/payment-sessions` та
  `POST /store/carts/:id/complete` — провайдер оплати має бути в
  `allowedProviders` (фактично блокує лише mixed).

## 4. Доставка: та сама Нова Пошта, окрема опція

Опція «Нова Пошта (відправлення постачальника)» (константа
`DROPSHIP_SHIPPING_OPTION_NAME` в `src/lib/kosmotech-dropship-constants.ts`,
дубль у `apps/storefront/src/lib/cart-kind.ts`):

- живе на **реальному провайдері `novaposhta`** з fulfillment-опцією
  `novaposhta-warehouse` (`data.id`), тому `validateFulfillmentData` пише
  `np_kind: "warehouse"` як звичайно;
- лежить на окремому shipping-профілі **Kosmotech** (type `kosmotech`) разом
  з усіма дропшип-товарами — дропшип-кошик резолвить рівно її, власні кошики
  її не бачать (профіль = механізм розділення);
- сабскрайбер `order-placed-novaposhta.ts` СВІДОМО спрацьовує і для
  дропшип-замовлень — ТТН створюється з акаунта NOVA, як для власних; ніяких
  guard-ів по постачальнику в ньому більше немає;
- NP-пікер чекаута перевикористовується як є (звичайні `np_*` ключі в data).

Локально опцію створює `seed.ts`; на проді — руками в адмінці (див. §10.2).

## 5. Черга дропшип-заявок

Сабскрайбер `src/subscribers/order-placed-kosmotech.ts` (`order.placed`):
якщо замовлення класифіковане "dropship" → пише
`order.metadata.kosmotech_queue = { text, status: "new", created_at }` і шле
лист менеджеру (env `KOSMOTECH_QUEUE_EMAIL` / `KOSMOTECH_QUEUE_FROM`; акаунт
має бути в `MAIL_ACCOUNTS`). ТТН у момент листа зазвичай ще створюється —
актуальний номер завжди видно на адмін-сторінці (join з fulfillment наживо).

Адмін-сторінка **Kosmotech** (`src/admin/routes/kosmotech/page.tsx`, іконка
вантажівки) — черга зі статусами `new → placed → shipped`:

- колонка ТТН (клік = копіювання) — з `fulfillment.data.np_ttn` наживо;
- кнопка **«Excel для імпорту»** — готовий .xlsx (колонки `article`/`count`)
  з роута `GET /admin/kosmotech/queue/:id/import-file`;
- кнопка «Копіювати артикули» — той самий вміст текстом;
- кнопка «Відкрити кабінет Kosmotech» → `newb2b.kosmotech.com.ua/ua/checkout/`.

Ручний крок менеджера (v1, свідомо): у кабінеті Kosmotech — «Імпорт
замовлення з Excel» → файл з адмінки → спосіб доставки «Відправка по ТТН» →
вставити ТТН → «Оформити замовлення». Кабінет сам підтягне дані отримувача.
(v2-опція — бот, що робить це сам; відкладено: крихкість до верстки кабінету,
зберігання кредів. Якщо повернемось — автоматизувати лише наповнення кошика.)

## 6. Storefront

- Вибір оплати: обидва варіанти (картка / післяплата) для всіх кошиків,
  включно з дропшип — жодного COD-форсингу.
- Бейдж «Зі складу партнера» (`dropshipBadge`) на дропшип-позиціях у чекауті;
  пояснення на кроках доставки й оплати (`dropshipShippingNote`,
  `dropshipCodDescription`) — обидві мови через `src/i18n/dictionaries.ts`.
- Змішаний кошик: 400 від middleware → людський тост.
- Дропшип-опція доставки — звичайний NP-warehouse флоу (пікер міста/відділення).

## 7. Env (прод)

```bash
KOSMOTECH_QUEUE_EMAIL=business@novastore.com.ua   # куди падають заявки
KOSMOTECH_QUEUE_FROM=business@novastore.com.ua    # від кого (має бути в MAIL_ACCOUNTS!)
```

Той самий нюанс, що й раніше: якщо адреси `KOSMOTECH_QUEUE_FROM` немає в
`MAIL_ACCOUNTS`, `getAccount()` мовчки візьме `MAIL_ACCOUNTS[0]`.

## 8. Юніт-тести

`tests/unit/kosmotech-dropship.spec.ts`: classifyCart (усі 4 випадки),
allowedProviders (own=dropship, mixed/empty порожні), buildKosmotechImportRows
(фільтр без-SKU), buildDropshipOrderText (формат, ТТН-плейсхолдер, BigNumber
total, фолбеки).

## 9. Локальна перевірка

```bash
docker compose up -d            # postgres (+ mail за потреби)
# apps/backend/.env: ALLOW_TEST_PAYMENTS=true, БЕЗ реальних MAIL_*/MONO_TOKEN
npx medusa db:migrate && npm run seed
# створити 2-3 товари з metadata.kosmotech (тимчасово руками в адмінці або
# скриптом імпорту, коли з'явиться файл постачальника), shipping profile Kosmotech
```

Тест-матриця (кожен кейс — UA/EN, десктоп + мобільний 390×844):

| # | Кейс | Очікування |
|---|---|---|
| 1 | Кошик з власним товаром → чекаут | Доставка: Standard/Express (без дропшип-опції). Оплата: картка/післяплата |
| 2 | Кошик з kosmotech-товаром → чекаут | Доставка: ЛИШЕ «Нова Пошта (відправлення постачальника)» з NP-пікером. Оплата: картка/післяплата — обидві |
| 3 | Спроба змішати | 400 + тост; кошик не змінився |
| 4 | Завершити дропшип-замовлення | `metadata.kosmotech_queue.status="new"`; авто-ТТН СТВОРЮЄТЬСЯ (лог `[NovaPoshta]`; без NP-ключа — помилка в лозі, не падіння); заявка на адмін-сторінці Kosmotech; лист менеджеру (GreenMail) |
| 5 | «Excel для імпорту» | Валідний .xlsx: заголовки article/count, по рядку на SKU |
| 6 | ТТН на сторінці | Після створення fulfillment — номер видно, клік копіює |
| 7 | Статуси | new → «Оформлено» → placed → «Відвантажене» → shipped; фільтр працює |

Приймання «головної мети» (кошик Kosmotech наповнюється): локально не
відтворюється — кабінет зовнішній. Акцепт на проді: завантажити Excel з
адмінки в «Імпорт замовлення з Excel» кабінету → позиції з правильними
кількостями з'являються в кошику; «Відправка по ТТН» приймає номер з адмінки.

## 10. Прод-розгортання (коротко)

1. **Код:** деплой за [DEPLOY.md](DEPLOY.md); env з §7.
2. **Разова очистка БД від старого постачальника:**
   `npx medusa exec ./cleanup-legacy-dropship.ts` (див. шапку скрипта; після
   успішного запуску на проді файл можна видалити з репозиторію).
3. **Locations & Shipping (руками в адмінці):**
   - Shipping profile «Kosmotech», type `kosmotech`;
   - Shipping option type «Kosmotech», code `kosmotech`;
   - у зоні «Ukraine» → Create option: Name = рядок-в-рядок
     `Нова Пошта (відправлення постачальника)`, profile **Kosmotech**,
     provider **Novaposhta**, fulfillment option **novaposhta-warehouse**,
     Enable in store, ціна 0 UAH. Точна назва — єдине, що звіряє код
     (`DROPSHIP_SHIPPING_OPTION_NAME`).
   - Типові помилки ті самі, що й колись: чужий профіль → опція світиться не
     тим кошикам; але провайдер тепер САМЕ Novaposhta — це правильно і потрібно.
4. **Товари:** імпорт з файлу постачальника (скрипт буде додано), канали
   «NOVA Online Store» (+ окремий організаційний канал за бажанням), draft →
   публікація партії → скинути кеш сторфронта (`products,categories` +
   `product-<handle>`).
5. **Guardrail-тести без грошей:** змішаний кошик → 400; дропшип-кошик бачить
   лише дропшип-опцію і обидва способи оплати; власний кошик — навпаки.
6. **Наскрізний тест:** реальне замовлення на собі → ТТН в адмінці → Excel →
   кабінет Kosmotech → «Відправка по ТТН» → звірити, що замовлення в кабінеті
   отримало правильні позиції і ТТН → статуси в адмін-черзі.

## Відомі обмеження v1 / беклог v2

- Змішані кошики заборонені (v2: авто-розбиття на два замовлення).
- Оформлення в кабінеті Kosmotech — ручний крок з готовим Excel і ТТН
  (v2: бот для наповнення кошика).
- Наявність/ціни дропшип-товарів не синхронізуються автоматично (v2: джоба
  на прайс/фід постачальника, якщо Kosmotech його надає).
- Статус «Відвантажене» з кабінету переноситься в чергу вручну (v2: синк).
