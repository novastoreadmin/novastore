# NOVA ↔ Eight Sleep: звіт про UX-паритет

Мета: досягти рівня плавності, анімацій і загального полішу eightsleep.com,
зберігши власну айдентику NOVA (темний преміум-канвас, типографічний hero,
власні фото й копірайт). Повна деконструкція Eight Sleep лежить окремо в
`../eightsleep-ux-teardown-and-electronics-adaptation.md` (частини 1–2 — патерни
та специфікації; цей звіт — прикладний зріз саме для novastore.com.ua).

## 2. Знайдені й виправлені дефекти

### 2.1. «Чорний hero» (критичний)
GSAP-пастка: скраб-твіни параллаксу (`gsap.to(headline …, scrub)`) ініціалізувалися,
поки entrance-таймлайн тримав елементи у from-стані (`opacity:0, y:80`), і
знімали ці значення як стартові. На `scrollY=0` заголовок лишався невидимим
(заміряно на проді: `opacity:0, translateY(80px)`).
**Фікс:** `immediateRender:false` на всіх скраб-твінах hero
([hero.tsx](apps/storefront/src/components/home/hero.tsx)).
**Правило для розробників:** будь-який `gsap.to(...)` зі `scrollTrigger.scrub`,
який торкається властивостей, що анімуються ще й entrance-твіном, зобов'язаний
мати `immediateRender:false` (або використовуйте `fromTo`).

### 2.2. Биті зображення pinned-секції (критичний)
`product-storytelling.tsx` посилався на 4 неіснуючі файли
`/images/home/feature-*.jpg` — на проді картки рендерилися порожніми з alt-текстом.
**Фікс:** файли створені з реальних продуктових фото
(`public/images/home/feature-{transfer,unibody,power,display}.jpg`).

## 3. Реалізовано в цьому проході

1. **Lenis smooth scroll** ([smooth-scroll.tsx](apps/storefront/src/components/layout/smooth-scroll.tsx)):
   інерційний скрол, синхронізований із ScrollTrigger (`lenis.on('scroll',
   ScrollTrigger.update)` + `gsap.ticker` + `lagSmoothing(0)`). Це головний
   інгредієнт «того самого» відчуття скраб-сцен. Touch-пристрої лишаються на
   нативному скролі (дефолт Lenis) — мобільний UX не змінюється.
2. **`prefers-reduced-motion`** наскрізно:
   - framer-motion: `<MotionConfig reducedMotion="user">` у providers;
   - GSAP: тривалості → ~0 ([gsap-config.ts](apps/storefront/src/animations/gsap-config.ts));
   - Lenis: не вмикається взагалі.
3. **Хедер**: висота 72→60px при скролі (плюс наявний glass-перехід) — «стискання»
   як у референса.
4. Виправлення §2.1–2.2.

## 4. Рекомендації наступної хвилі (за пріоритетом)

1. **Медіа для hero**: зараз hero суто типографічний з орбітальним гло. Наступний
   крок до кінематографічності — повільний ambient-loop (webm ≤2МБ, poster,
   `prefers-reduced-motion` → статичний кадр) або великий продуктовий рендер.
2. **Count-up** на числових статах (10Gbps/240W/8K секції): framer `useInView` +
   анімація значення; лише для чистих чисел, суфікси статичні.
3. **Прод-чистота асетів**: перевірити всі `<Image>` на існування файлів у CI
   (простий скрипт-глоб по `src=`/public) — щоб §2.2 не повторився.
4. **Легкий parallax на фото секцій** (yPercent ±6, scrub) — тільки з
   `immediateRender:false` (див. правило §2.1).
5. **Продуктова сторінка**: додати sticky buy-бар на мобільному (патерн Eight
   Sleep product page) — окрема ітерація, зачіпає checkout-флоу.

## 5. Гайдлайни безпечного застосування

- Кожна анімаційна зміна проходить чекліст: (а) `npx tsc --noEmit`, (б) локальний
  прогін `npm run dev` з перевіркою консолі, (в) скрол згори до низу на 1512px і
  375px, (г) перевірка з увімкненим "Emulate CSS prefers-reduced-motion" у DevTools.
- Не додавати нових бібліотек анімації: стек зафіксований (GSAP + ScrollTrigger +
  framer-motion + Lenis). Дублювання рушіїв = розсинхрон і вага.
- Тайминги/ізінги — тільки токени з `animations/variants.ts`
  (ease `[0.16,1,0.3,1]`, entrance 0.5–0.8s, stagger 0.08–0.15) — не хардкодити
  нові криві поелементно.
- Деплой сторфронта: стандартний (`npm run build` + `pm2 restart storefront`,
  див. DEPLOY.md §3). Зміни цього проходу не торкаються бекенда.
